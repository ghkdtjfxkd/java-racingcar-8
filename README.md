# java-racingcar-precourse

> Event-Driven-Architecture로 구현하는 자동차 경주

### 🧩EventBus
- [x] Event Bus
- [ ] Event Bus 에서 사용될 이벤트 스키마 정의

---
### 🏎️ Entry
- [ ] 입력받은 참가자 문자열을 파싱한다.
- [ ] 입력받은 참가자 문자열을 검증한다.
- [ ] 자동차를 움직인다.
- [ ] 자동차의 움직인 거리를 반환한다.

---
### 🛣️ Lap
- [ ] 랩 횟수가 남았다는 이벤트를 받으면 랩 진행중 상태로 바꾸고 랩 진행 이벤트 반환
- [ ] 경기 기록됨 이벤트를 받으면 랩 대기중 상태로 바꾸고 랩 종료 이벤트를 반환

---
###  💻 I/O 
- [ ] 사용자로부터 참여할 자동차 목록을 입력 받는다.
- [ ] 사용자로부터 시도할 횟수(Lap Count)를 입력 받는다.
- [ ] 실행 결과를 출력한다.
<details>
<summary>입/출력 책임에 대한 고민</summary>

순수자바 + CLI 환경에서 EDA 구현을 위해 모듈러 모놀리식 아키텍처로 구현을 택했다.
입력을 각 모듈에서 받는게 맞을까? 아니면 I/O를 담당하는 모듈을 별도로 두는게 맞을까?
- 순수자바 + CLI 환경에서 입/출력을 한다.
- 분산 환경에서 입력이 들어오는 경우를 대입해서 생각해보자. 
- 입력과 출력은 실제 구동하는 Application.main()을 실행하면서 들어온다. 
- Application.main()에 InputView(FE)가 있는게 자연스럽다. ->  CLI에 입력 하기 때문에
- Application.main()에 OutputView(FE)가 있는게 자연스럽다. -> CLI로 결과를 보기 때문에
- 분산 환경에서 FE를 하나의 프로젝트로 두는가? -> 백엔드가 분산되어도, 사용자가 보는 단일한 경험을 위해 모놀리식 프론트엔드?
</details>

### 🏟️ RACE
- [ ] 남은 랩 횟수에 따른 이벤트를 발행한다.
  - [ ] 남은 랩 횟수가 없으면 경기 종료 이벤트를 발행한다.
  - [ ] 남은 랩 횟수가 있으면 랩 횟수 남음 이벤트를 발행한다.
